04 / WHAT THE DATA TEACHES US

Three lessons beyond
Pokémon.

Underneath the game theme are principles that matter in real BI, public sector and commercial analytics.

LEARNING / 01

Averages conceal extremes.

The total base stat is just the sum of six attributes. It hides how dramatically a species can specialise in HP, Speed or Special Attack.

LEARNING / 02

Weights express priorities.

Give more importance to a different attribute and the ranking can change. Model assumptions are decisions, and transparent models expose them.

LEARNING / 03

Correlation isn't a result.

These are species-level base stats. Actual battles depend on level, nature, IVs, EVs, typing, abilities, moves, items and player choices.

05 / ENGINEERING NOTES

Make the model readable.

The project uses a six-axis radar, two transparent stat tables and a weighted-average scoring function. The underlying data is embedded so the demo does not require a live API connection.

Source and data cleaning

The six base stat fields are aligned in identical order across the two standard-form records. Both datasets are attributed to PokéAPI and independently cross-checked against specialist Pokédex references.

What the index really measures

Six base values are multiplied by the chosen category weights, summed and divided by the sum of those six weights. The output retains units of base stat points, and it is not a calibrated probability or battle-performance score.

const weightedScore = (s, bulk, offence, speed) => {
  const weights = [bulk, offence, bulk, offence, bulk, speed];
  return s.reduce((sum, value, i) =>
    sum + value * weights[i], 0
  ) / weights.reduce((sum, weight) => sum + weight, 0);
};
// The user chooses the weights. The result is not a match winner.
